# zuspark bug hunt, 2026-11-12

Commit `17f825c`. Hunters: 3 on Fable (`claude-fable-5-2`), run one at a
time, each with only its brief. Slices: the R layer; the Spark Connect
protocol, both directions; lifecycle and ownership. Coordinator on Opus
5.5. Built here: the pure-R package on macOS (Darwin 24.6), R 4.6.2,
zugrpc `ed345d1`, zuhttp `7c53641`, zuarrow `b13d340`, zuproto `1388989`,
DBI 1.3.0, dbplyr 2.6.0. The counterparts were:

- a scripted fake transport (`zuspark.transport`);
- a recording proxy over the real transport;
- Spark Connect 4.2.1 servers in podman on 127.0.0.1, one plain and one
  cutting its streams after 1 s or 1 MiB.

Unverified, so inspection only:

- Spark 3.5 servers (no `start_offset`, no progress responses, no
  ReleaseSession);
- TLS and Databricks against a real workspace;
- Windows, and a latin1 native locale;
- R 4.1;
- a real SIGINT during a live `spark_connect()`.

Every reproduced trigger was re-run by the coordinator on a fresh
install of `17f825c` (`rerun/` in the probes). The target map is
`2026-11-12-bug-hunt-probes/target-map.md`. The hunters' scripts are
under `hunter-1/` to `hunter-3/`. Their paths are absolute to the
hunt's scratch directory: set them to a scratch library and a
loopback server before running.

The yield is 26 new issues, #124 to #149: 5 blocking, 13 required, 7
suggestions and 1 question. Two more findings were already open, #103
and #104, and gained siblings in comments. Six root causes were found
by more than one hunter: #130, #136, #137, #145, #104 and #103.

## 1. Escape `$` in DBI string literals and identifiers — #124, high, reproduced

- Where: [`R/dbi.R:79`](../../R/dbi.R#L79) (`spark_quote_string()`),
  [`R/dbi.R:70`](../../R/dbi.R#L70) (`spark_quote_identifier()`)
- Trigger: `dbWriteTable(con, "t", data.frame(s = c("price ${amount}",
  "${spark.app.name}")), temporary = TRUE)`, then `dbReadTable()`.
  - The values come back as `"price "` and `"Spark Connect server"`.
  - `${env:HOME}` and `${system:java.version}` put the server's
    environment into the table.
  - An identifier `${spark.app.name}` names the column
    `Spark Connect server`.
- Cause: `spark.sql.variable.substitute` is on by default in Spark 4.2.1
  and substitutes before parsing; the quoting escapes only `\` and `'`.
- Fix: write `$` as `\u0024` in string literals, which was checked live;
  refuse `${` in identifiers.
- Family: 4 (the parser is not the text's first reader). Siblings
  checked: string literals and identifiers both fail. `dbQuoteLiteral()`,
  `dbWriteTable()` and `dbAppendTable()` all go through these two
  functions. dbplyr's route fails too (#125).
- Test the suite lacked: a live round trip of `${…}` strings and
  identifiers.

## 2. Route dbplyr's string escaping through `dbQuoteString()` — #125, high, reproduced

- Where: [`R/dbi.R:479`](../../R/dbi.R#L479) (`register_dbplyr()`)
- Trigger: for a table holding `"back\\slash"`:
  - `filter(tbl(con, "t"), s == "back\\slash")` returns 0 rows.
  - `copy_to()` stores `"backslash"`, and `"C:\\new\\table"` with a
    real newline and tab.
- Cause: only dbplyr's `*.Spark SQL` methods are registered, and its
  escaping doubles `'` and leaves `\` alone. Spark reads `\` as an escape.
- Fix: register `sql_escape_string()` for `ZusparkConnection` with
  zuspark's quoting.
- Family: 3 (the escaping rule fixed on one route, not its sibling).
  Siblings checked: `filter()`, `copy_to()`, `escape()`.
- Test the suite lacked: the same strings through `dbQuoteString()`,
  `copy_to()` and `filter()`, compared live.

## 3. Write `integer64` without relying on bit64 being loaded — #126, high, reproduced

- Where: [`R/dbi.R:118`](../../R/dbi.R#L118),
  [`R/utils.R:23`](../../R/utils.R#L23)
- Trigger: without bit64 loaded, `dbQuoteLiteral(con, <integer64 1, 5>)`
  gives `CAST(4.94065645841247e-324 AS BIGINT)`; Spark stores 0 and 0.
- Cause: `as.character()` and `format()` dispatch to bit64 only when its
  namespace is loaded.
- Fix: call bit64's method explicitly, or refuse `integer64` without it.
- Family: none exactly; see Cross-cutting. Siblings checked:
  `spark_literals()` and `scalar_text()` (`spark_config()`) both fail.
- Test the suite lacked: literals for `integer64` in a callr child
  without bit64.

## 4. Refuse non-raw list columns and POSIXlt instead of writing BINARY — #127, high, reproduced

- Where: [`R/dbi.R:101`](../../R/dbi.R#L101),
  [`R/dbi.R:120`](../../R/dbi.R#L120)
- Trigger: `dbQuoteLiteral(con, list(1:3, 300L, "a"))` gives `X'010203'`,
  `X'00'` and `X'00'`.
  - POSIXlt and `numeric_version` map to `BINARY`.
  - A POSIXlt value becomes its 11 fields in one blob.
- Cause: any `is.list()` is BINARY; `as.raw()` coerces each element.
- Fix: accept only lists of raw or NULL and `blob`; convert POSIXlt;
  refuse the rest.
- Family: 3 (`difftime` is refused; its siblings are not). Siblings
  checked: POSIXlt, `numeric_version`, a nested data frame and a matrix
  column all fail.
- Test the suite lacked: `spark_data_type()` and `spark_literals()` over
  the value matrix.

## 5. Insert `...` parameters before a query or fragment — #128, high, reproduced

- Where: [`R/session.R:393`](../../R/session.R#L393),
  [`R/url.R:46`](../../R/url.R#L46)
- Trigger: `spark_connect("sc://h.example?x=1", token = "t")`, and the same
  with `/#frag`.
  - The channel is `http://`, and no `authorization` header is sent.
  - There is no error.
- Cause: parameters are appended after the `?` or `#`, which the parser
  then drops.
- Fix: merge `...` into the parsed settings, or refuse `?` and `#`.
- Family: 4 (a component the code forgets). Siblings checked:
  `spark_connect_databricks()` strips `?` and `#` from the host first,
  so it holds.
- Test the suite lacked: `token =` through urls with `?`, `#`, `/`, an
  existing `;` and none.

## 6. Refuse a parameter value containing `=` — #129, medium, reproduced

- Where: [`R/url.R:84`](../../R/url.R#L84)
- Trigger: `sc://h/;token=abc=` sends `Bearer abc`.
  - `token=abc==` is refused.
  - `token = "abc="` as an argument sends `abc=`.
- Cause: `strsplit()` drops one trailing empty piece.
- Fix: split at the first `=` and pick one rule. PySpark refuses any
  value with `=`; that is from reading its source, not a run.
- Family: 1. Siblings checked: `k==` parses as `k = ""`.
- Test the suite lacked: `k=a=`, `k=a==`, `k==`, `k=` and `=v` against
  PySpark (#110).

## 11. Treat any failure of the final release as best effort, except a session error — #134, medium, reproduced

- Where: [`R/execute.R:281`](../../R/execute.R#L281)
- Trigger: ReleaseExecute answers with Spark's ErrorInfo, or with bytes
  that don't decode.
  - `spark_collect()` and an `INSERT` fail after their result was
    complete.
  - Live: closing the session before the release fails a complete
    collect with `INVALID_HANDLE.SESSION_CLOSED`.
  - Real Spark answers releases with ErrorInfo
    (`OPERATION_STATUS_MISMATCH`).
- Cause: only `zuspark_rpc_error` is caught. Design §7.4 (#27) wants the
  release after ResultComplete best effort, so a statement is not run
  twice.
- Family: 3. Siblings checked: the inline release fails the same way;
  the abandonment release is inside `try()` and holds.
- Test the suite lacked: final and inline releases answering each error
  kind.

## 26. Should an empty clean stream count as a stall? — #149, question, reproduced

The three-stall limit is a recorded decision (§7.4, 2026-11-05).
Live, it has a consequence that decision does not consider:

- On a server cutting streams every second, with progress reports off
  (session-settable), a 6-second INSERT fails after 3 s.
- The release-all that follows cancels the statement.
- On Spark 3.5, which sends no progress, the window would be about
  6 minutes under default settings (inspection).

## Cross-cutting

- **Text Spark rewrites before it parses** (#124) and **two escaping
  routes** (#125): the SQL zuspark writes is read by more than one
  reader. The candidate rule for `correctness.md`: *for text another
  program parses, test against that program's whole reading of it,
  every pre-pass included (substitution, escapes, encoding), not against
  the grammar*.
- **Behaviour that depends on another package being loaded** (#126):
  S3 dispatch on a class whose methods live in a Suggests package. The
  candidate rule: *a class from an unloaded package is formatted by its
  bits; dispatch explicitly, or refuse the class*. It fits none of the
  four families; the closest is family 2's "state the caller cannot see".
- **Best effort that is not best effort** (#134, #135, #147, #139): the
  cleanup after a completed or abandoned execution is meant never to fail
  the statement. It does when the condition class, the stream's tail or
  the deadline differs from the one case tested.
- **Copies of a stateful environment** (#138, #141, #140): one
  `zuspark_connection` reached from a fork, an unserialised copy or a DBI
  result. Each copy carries state it does not own: a finaliser, a
  released flag, rows.

## Held: what was probed and stood

- **The `sc://` parser:** scheme, path, IPv6, port range, userinfo,
  percent-decoding, the duplicate-parameter rule, `use_ssl`, the empty
  token.
- **`...` to string:** a round trip of `;`, `=`, `%`, `+`, `/`,
  non-ASCII, newline and large numbers.
- **Argument precedence:** `user_id`, `user_agent`, `session_id`,
  `token`, and the environment variables.
- **`deadline`:** each invalid value is refused; 2 s, 30 s and the 5 s
  finaliser are measured exactly against a blackhole server.
- **Headers:** invalid names and values refused; `authorization` is
  replaced by the token.
- **`client_type()`:** the 2048 limit counts encoded length.
- **`spark_connect_databricks()`:** host normalisation, the token round
  trip, the session and cluster headers.
- **`spark_config()`:** reads, sets, unsets and the restore round trip,
  live, including `""`, non-ASCII and latin1 values.
- **`spark_schema()`:** 46 expressions compared live with `typeof()`;
  only an explicit `COLLATE UTF8_BINARY` differs (printed `string`).
- **DBI literal round trips:** 29 awkward strings (except `${`), 25
  doubles, Dates, POSIXct, `integer64` with bit64 loaded, blobs; all
  unchanged under a hostile `OutDec`, `TZ` and `digits`.
- **DBI quoting, writes, fetching and accessors** after each step;
  dbplyr `tbl()`, `filter()` on numbers, `count()`, `compute()` and
  `copy_to()` of factors and dates.
- **The inline release, straddled:** 14 to 17 and 31 to 33 responses
  release at 16 and 32, and not when ResultComplete is the 16th.
- **A cut at every one of 40 positions:** the same data frame each time.
  Live, on the cutting server: `range(3e6)`, 45 reattaches, ids exact,
  one release-all.
- **Side effects never sent twice:** cuts injected on an INSERT at six
  points; a lost ExecutePlan re-sent only on OPERATION_NOT_FOUND, and
  the INSERT applied once.
- **Protocol checks:** a changed operation or session id, undecodable
  messages, every `start_offset` and `row_count` lie, buffers of 15 to
  200 batches.
- **Interrupts:** live SIGINT during collect, execute, `dbGetQuery`,
  connect, config, schema and disconnect cancels the server job, and the
  connection stays usable.
- **Connection life:** disconnect twice, every verb after disconnect,
  connect failures at each call, `saveRDS()` into another process, two
  connections with one session id, a server restart.
- **`spark_fetch()`'s stream** after disconnect, after a re-run and
  after `gc()`; #114's sequences hold.

## Not reproduced, and by design

- `deadline = Inf`: reported as escaping without `zuspark_error`. It is
  a `zuspark_rpc_error` raised at the first call, so the class holds;
  only the late refusal stands (#144).
- A non-ASCII `user_id` in the URL: it failed only under `LC_ALL=C`, and
  is reported there (#133).
- The three-stall limit: by design (§7.4); its consequence is the
  question in #149.
- A session left on the server when R quits without
  `spark_disconnect()`: by design (§7.2, the finaliser is best effort
  and the server's idle timeout ends it).
- Reading a `spark_fetch()` stream twice gives 0 rows: nanoarrow's
  stream semantics, documented by zuarrow.
- `spark_error_details()` works once per error: the server drops the
  details after the first fetch.
